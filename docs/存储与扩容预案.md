# 存储与扩容预案

本仓库随同步持续增长，GitHub 各层限额不同，触发线到了再动手，现在无需处理。

## 现状与限额

| 层 | 限额 | 现状（2026-10） | 增长预估 |
|---|---|---|---|
| Git 仓库 | 建议 <1GB，**硬限 5GB**，单文件 ≤100MB | 约 0.5GB（纯文本压缩率高） | onehu 全量追平约 +0.4GB |
| GitHub Pages 发布站 | **≤1GB**，100GB/月流量（软限），10 构建/时 | **约 190MB**（索引卡片页 ~115MB + Pagefind 索引 ~65MB + 索引 JSON 等） | **每千篇约 +18MB**（卡片页 11KB + 索引 6KB） |
| GitHub Actions | 公共仓库免费；定时任务 60 天无活动自动禁用 | keepalive 已配置 | — |
| Release 资产 | 单文件 2GiB，总量宽松 | 每月全量快照 ZIP | — |
| raw.githubusercontent | 无明确限额，CORS 全开放 | 全文按需拉取的数据通道 | jsDelivr 镜像兜底 |

## 已落地的架构：索引卡片 + 按需正文（2026-10 改版）

此前文章页内嵌全文，站点体积随正文线性膨胀（10,416 篇时已达 **647MB**，逼近 1GB 上限）。
现已改为：

- **Pages 只存「索引卡片页」**：每篇文章一个轻量页面（平均 11KB）＝标题 + 元信息 +
  **可见的开头 1500 字**（同时作为 Pagefind 的索引窗口，窗口不缩水）+ 精简页框；
- **全文不部署**：阅读时前端从 `raw.githubusercontent.com` 直链拉取 Markdown 渲染，
  `cdn.jsdelivr.net/gh/...` 作备用线路，均失败则保留开头部分并给出重试/GitHub 链接；
- **搜索索引窗口不变**：仍是「标题 + 正文开头 1500 字」，Pagefind 索引 ~65MB（含子结果定位）。

改版收益：**647MB → 190MB**，增长斜率从 ~58KB/篇 降到 ~18KB/篇；
onehu 追平（预计 +4000 篇）后约 260MB，2 万篇时约 330MB，1GB 上限内余量充足。

## 已内置的体积控制

- 正文清洗删掉了 `<br>`（90 万个）、`&emsp;`（1073 万个）、源站水印（8356 处）；
- 卡片页页框精简（面包屑替代全量导航，页脚单行），单页框架 <2KB；
- 同步按「标题归一化指纹」跨源去重（`scripts/cleanlib.py: norm_title`）；
- `data/articles_index.json`（约 2.9MB）挂载为静态资源，供「全部文章」即时筛选，
  其中 `l` 字段由 `cleanlib.py: hugo_slug` 复现 Hugo urlize 规则生成永久链接
  （已在全库 10,416 篇上验证与实际 URL 100% 一致，改动需与 Hugo 版本联测）。

## 触发线与动作

### ① 站点发布体积 > 850MB（按当前斜率约在 5 万篇时触及，短期无忧）

二选一：

- **A. 缩小搜索窗口**：卡片页摘要与 Pagefind 窗口 1500 → 800 字（索引再减半）；
- **B. 迁移 Cloudflare Pages（推荐）**：免费、流量不限、无 1GB 限制，
  但每个部署 ≤2 万文件、单文件 ≤25MB —— 卡片页架构可直接平移，
  或进一步改为「分卷 JSON + 单页阅读器」把文件数压到几百个。

### ② Git 仓库 > 3.5GB（含盐选文库 2 万+ 篇时可能触发）

- **按源拆分数据仓库**：主仓库只留代码与站点，`我不是盐神/`、`知乎搬运工/`、
  `盐选文库/` 各自独立仓库（5GB 限额按仓库计），Actions 用 checkout 多仓库聚合构建；
- 全量历史随时可从 Releases 快照恢复。

### ③ 有自定义域名时

- **Cloudflare R2 免费档**：10GB 存储 + 流量完全免费 + 每月 1000 万次读，
  绑定自定义域名即可静态托管整个站点，是最终的容量兜底。

### ④ 明确不做

- **Git LFS**：免费额度仅 1GB 存储/1GB 带宽每月，纯文本场景没有收益；
- **正文存 Release、站点按需拉取**：raw 直链方案已覆盖此需求且更简单。

## 搜索体验说明

Pagefind（1.5+）内置中文分词，但查询与文档分词可能不对齐：
长词组偶尔 0 结果时，站点会自动给出简化关键词建议（去停用词 / 2~4 字切分重搜）。
标题搜索覆盖率最高；「全部文章」浏览区的即时筛选同样基于标题（含专栏名）。

## 已知问题与兜底

- **Hugo 落盘竞态**：0.154/0.168 均复现，直写磁盘时单次构建随机 3~8 页
  （~0.05%）页尾块重复输出或写入坏字节；与并发度（GOMAXPROCS）、
  minify、二进制来源均无关。**规避**：`--renderToMemory` 整站内存渲染后
  统一落盘，实测连续多次 0 坏页；另以 `scripts/verify_site.py`
  全量校验作兜底（发现坏页自动重建，最多 3 次）。
