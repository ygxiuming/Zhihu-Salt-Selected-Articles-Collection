# 存储与扩容预案

本仓库随同步持续增长，GitHub 各层限额不同，触发线到了再动手，现在无需处理。

## 现状与限额

| 层 | 限额 | 现状（2026-10） | 增长预估 |
|---|---|---|---|
| Git 仓库 | 建议 <1GB，**硬限 5GB**，单文件 ≤100MB | 约 0.5GB（纯文本压缩率高） | onehu 全量追平约 +0.4GB |
| GitHub Pages 发布站 | **≤1GB**，100GB/月流量（软限），10 构建/时 | 0.58GB（HTML 0.53 + 搜索索引 0.056） | 见下方触发线 |
| GitHub Actions | 公共仓库免费；定时任务 60 天无活动自动禁用 | keepalive 已配置 | — |
| Release 资产 | 单文件 2GiB，总量宽松 | 每月全量快照 ZIP | — |

## 已内置的体积控制

- 正文清洗删掉了 `<br>`（90 万个）、`&emsp;`（1073 万个）、源站水印（8356 处），
  仅此一项减少约 80MB；
- 搜索索引只收录**标题 + 正文开头 1500 字**（Pagefind 对中文做字符级切分，
  全文索引体积与正文相当，8200 页全文索引实测 451MB）；窗口在
  `layouts/_default/single.html` 的 `truncate 1500` 处调整；
- 同步按「标题归一化指纹」跨源去重（`scripts/cleanlib.py: norm_title`）。

## 触发线与动作

### ① 站点发布体积 > 850MB（当前 0.58GB，onehu 追平后预计 ~0.9GB）

二选一：

- **A. 缩小搜索窗口**：`truncate 1500` → `800`（索引再减半，搜索退化为标题+开头）；
- **B. 迁移 Cloudflare Pages（推荐）**：免费、流量不限、无 1GB 限制，
  但每个部署 ≤2 万文件、单文件 ≤25MB —— 文章页改为「分卷 JSON + 单页阅读器」，
  部署文件数恒定几百个；`*.pages.dev` 免费域名，顺带改善国内访问。

### ② 文章总量 > 3.5GB（含盐选文库 2 万+ 篇时可能触发）

- **按源拆分数据仓库**：主仓库只留代码与站点，`我不是盐神/`、`知乎搬运工/`、
  `盐选文库/` 各自独立仓库（5GB 限额按仓库计），Actions 用 checkout 多仓库聚合构建；
- 全量历史随时可从 Releases 快照恢复。

### ③ 有自定义域名时

- **Cloudflare R2 免费档**：10GB 存储 + 流量完全免费（免出网费）+ 每月 1000 万次读，
  绑定自定义域名即可静态托管整个站点，是最终的容量兜底。

### ④ 明确不做

- **Git LFS**：免费额度仅 1GB 存储/1GB 带宽每月，纯文本场景没有收益；
- **正文存 Release、站点按需拉取**：阅读端依赖两个域名，复杂度高收益小。

## 搜索体验说明

Pagefind（1.5+）内置中文分词，但查询与文档分词可能不对齐：
长词组偶尔 0 结果时，拆成 2~4 字短词重搜即可（如「教授男朋友」）。
标题搜索覆盖率最高；正文级全文搜索需按预案 ①B 迁移后再评估。
